## マイルストーンの運用（`milestone` ラベル）

### 定義

- マイルストーン（英: milestone）は、コードで測れる完了条件を持つ到達点である。lm に Milestone という型は無く、完了条件を持つ Epic に `milestone:<名前>` ラベルを付けて表す。`lm list --label milestone:<名前>` で所属 Epic を列挙できる。
- 完了条件は、Epic に `done:<wait: ラベルと同じ書式>` のラベルとして書き、実行者が `wait:` ラベルと同じ測り方で判定する（書式は [gate.md](gate.md)「測って開ける待ちは wait: ラベルで表す」）。出荷版なら「タグ `v<版>` が公開されている」、到達目標なら「SLI（Service Level Indicator・サービスレベル指標）が閾値内にある」のように、到達した状態を書く。`done:` ラベルが複数あれば、すべてが成立したときに到達とみなす。
- 到達するまで崩さずに保つ状態（出荷条件）は、Epic に `hold:<wait: ラベルと同じ書式>` のラベルとして書く。`done:` が到達を判定する条件であるのに対し、`hold:` は到達までの間ずっと成立していなければならない条件で、一度満たしても後の変更で崩れれば不成立に戻る。マイルストーンの close は、`done:` の実測がすべて成立し、かつ `hold:` がすべて成立しているときにだけ判定する。基準: 保つべき状態を `done:` や子の作業として書くと、一度満たした時点で閉じ、その後の変更で崩れても誰も測らない。
- close したマイルストーンの `hold:` は測らない。マイルストーンを越えて保ち続ける状態は `hold:` に置かず、常設の不変条件としてリポジトリの運用規則の文書へ移す（「常設の SLO との区別」）。
- `hold-guard` ラベルは、`hold:` が崩れている間に実行者が塞ぐ段の印である。実行者は `hold:` の不成立を見つけたら是正の Bead を起票し、そのマイルストーンに属して `hold-guard` を持つ Bead をその是正の Bead に `blocks` で待たせ、`hold:` が成立に戻ったら塞ぎを外す。`hold-guard` を付けるのは、崩れたまま進めると出荷条件を崩したまま外へ出る段（タグの作成・公開先への反映など）である。測れない `hold:`・実行者の知らない種別の `hold:` は崩れている側に数える。
- `done:`・`hold:` ラベルを測るのは実行者（cron や CI のスケジュール実行で決まった間隔で起動し直されるエージェントなど）で、`lm` 本体は測らず、ラベルの意味だけを本書で定める。実行者を持たない環境では `done:`・`hold:` ラベルは測られないので、利用者かエージェントが題の成果と `hold:` の状態を確かめて Epic を `lm close` する。
- 実行者が条件を測るコードを probe と呼ぶ。実行者の probe に無い測り方が要るときは、probe を足す Bead を先に起票し、マイルストーンの Epic をその Bead に `blocks` で待たせる。
- done: の種別は題の成果を測るものを選ぶ。`done:file:<path>` は `wait:file:<path>` と同じく `<path>` の存在で満たす。題が「公開されている」「Release」を求めるなら `done:tag:<版>` を使い、repo 内のファイルの存在（`done:file`）で代えない。当てはまる種別が無ければ、実行者が起こす判定 Gate で判定者が種別を選ぶ。基準: ファイルの存在は公開や配布を示さず、題の成果が無いまま close される。
- マイルストーンの close を判定するときは、done: の実測だけでなく題の成果を実物（公開先・タグ・計測値）で確かめる。食い違えば close せず done: を書き直す。基準: done: が題より弱いと、実測が満たされても到達していない。
- 子 Bead がすべて終端になることは完了条件にしない。基準: 子の袋が空になることを条件にすると、到達した後に入った無関係な子で open が続き、起票が close を上回る間は到達しない。
- 期日は入力に持たない。`lm ahead` の `## Milestones` が出す見通しを出力として読む。

### 名前

- 呼び名は milestone（マイルストーン）に揃え、出荷版も到達目標も同じ `milestone:<名前>` の 1 種類で表す。出荷版かどうかは名前で表し、版名をそのまま名前にする（例: `milestone:v0.2610.0`）。goal・objective は SLO（Service Level Objective・サービスレベル目標）の O と衝突するので使わない。
- 名前は話題ではなく到達状態を要約する（例: `perf` ではなく `merge-p90-15m`）。Epic のタイトルには完了条件の全文を書く。

### 常設の SLO との区別

- 終わりの無い常設の SLO・不変条件はマイルストーンにしない。定義の正本はリポジトリの運用規則の文書に置き、Epic には置かない。
- SLO 違反の自動起票は、その SLI を完了条件に持つマイルストーンがあればその Epic の子に、無ければ `milestone` ラベルを持たない常設の運用 Epic の子に付ける。

### 起票と並び

- `lm ahead` の `## Milestones` に、所属する Bead の件数（Ready・作業中・段・Gate 待ち・残数）が出る。並びは優先度最小・同順なら残り最少の順（目の前のマイルストーンが先頭）で、先頭のマイルストーンに属する Ready の行には `milestone=<名前>` の印が付く。
- Bead を起票する前に `lm ahead` の `## Milestones` を見て、所属するマイルストーンの Epic があれば `--parent <Epic ID>` で付け、優先度をその Epic と同じ段に揃える。どのマイルストーンにも所属しないなら `--reason` にそう書く（SKILL.md「タスク消化サイクル」3.）。
- どのマイルストーンにも属さない Bead は `lm create --no-milestone "<理由>"` で起票する。`lm` は Bead に `exempt:milestone` ラベルを付け、理由を `no-milestone: <理由>` として履歴に残す。設定 `create.require_milestone` が真のときは、`--parent` も `--discovered-from` も付けない起票（Gate を除く）にこのフラグが要り、無ければ `lm` が拒否する。起票済みの Bead には `lm update <id> --add-label exempt:milestone --reason "<理由>"` で同じ印を付ける。
- 完了条件に要らない子は、その Epic から外す。

### 廃止

- マイルストーンを方針として廃止する Bead を起票したら、対象マイルストーンの Epic に `abolished-by:<その Bead の ID>` ラベルを `lm update <Epic ID> --add-label` で付ける。
- `abolished-by:` ラベルを持つ Epic の子孫は `lm ready` に出ず、`lm ahead` の `## Milestones` はその Epic を「廃止・棚卸し中」と表示する。
- 廃止した Epic の子は、close・他の Bead への吸収（`duplicates`）・別の Epic への付け替えのどれかに分け、全件を分け終えたら Epic を `lm close` する。実行者は廃止した Epic の子が停滞して見えても、再開の Bead を起票しない。基準: 印の無い廃止は Epic の子を Ready に残し、実行者が拾い続けるか停滞として再開させる。
