## 同時 claim・並行操作時の注意

- 複数のエージェント・プロセスが同じ Bead を同時に `--claim` しようとした場合、先に成功した側だけが `in_progress` になり、後から来た`--claim` は状態を変えずに固定行 `Rejected: <id> (already claimed by <actor>)` を返し Exit Code 1 で終わる。これはエラーではなく「既に他の誰かが着手した」という正常な通知であり、再試行の前に `lm show <id>` で現在の担当者を確認し、別の Bead を `lm ready` から選び直す。
- 書き込みロックの競合（同一データベースへの同時書き込み）でロック待ちがタイムアウトした場合は、上記の `Rejected:` とは別に固定行 `Busy: lock wait exceeded <n>ms`（標準エラー、Exit Code 1）が返る。これは「誰かが claim 済み」ではなく「今まさに他の書き込みが進行中で待ちきれなかった」ことを示すので、短い間隔を置いてから同じコマンドを再実行してよい。
- 複数エージェントを並行運用する場合、docs/env.md の `LM_NAMESPACE` でワークストリームを分けておくと、`lm ready --claim` の競合自体を減らせる。
