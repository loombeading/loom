# 重大度・期限・割り込み・保留の運用

`lm` は重大度・期限・割り込み・保存優先度と係数から実効優先度を導き、`lm ready` の並びを決める。本書は、利用者と実行者がそれらを「いつ・何で」付けるか、出力をどう読むかを書く。各項目の定義は[用語集](https://github.com/loombeading/loom/blob/main/docs/glossary.md)（「実効優先度」「--severity」「--due」「--expedite」「時間調整」「redetect_key」「revived_at」「係数」）にあり、本書は定義を用語集に任せて付け方と読み方だけを書く。

## 軸を使い分ける

- 壊れ方は重大度（`--severity`）で、やりたい時期は保存優先度（`--priority` の 1〜4）で、守る期日は期限（`--due`）で、今すぐ着手させたいことは割り込み（`--expedite`）で表す。基準: 急ぎを優先度の数字で表すと、急ぐ理由が消えても高いまま残り、期日と理由の記録が欠ける。
- 重大度は時間の経過では変えず、壊れ方の実測が変わったときだけ `lm update <id> --severity <1-4> --reason "<実測>"` で変える。基準: 時間で重大度を動かすと、事実の記録が並びの調整に使われ、何が壊れているかを読めなくなる。

## 起票のときに決める

- 重大度は証拠（エラー出力・赤い CI・止まった処理の時刻）を `--reason` に添えて `lm create --severity <1-4>` で付け、迷ったら上の段（小さい値）で始める。停止・赤い CI・消える資源の証拠があれば重大度 1 にする。基準: 下の段で始めると、上限と保留の判定が軽い側に倒れ、止まっているものが後回しになる。
- 止血できたら、止まったことを示す実測を `--reason` に書いて重大度を下げ、恒久対応は重大度 3 の別の Bead として `lm create --discovered-from <止血した Bead>` で起票する。基準: 止血と恒久対応を 1 件に混ぜると、止血の完了で閉じられず、重大度 1 のまま並びの先頭を占め続ける。

## 割り込み（`--expedite`）

- 他を止めてでも今やるときは、束の根の 1 件にだけ `lm update <id> --expedite <期間> --reason "<急ぐ理由>"` を付ける。前提と子には実効優先度が伝わるので、根の 1 件に付ければ足りる。基準: 子や前提ごとに付けると同時件数の上限をすぐ使い切り、本当の割り込みが拒否される。
- 期限が切れると割り込みは自動で外れ、未完了なら `lm ready`・`lm show` の行に `expedite-expired` の印が出る。印を見たら急ぐ理由が残っているかを確かめ、残っていれば理由を添えて同じコマンドで付け直し、残っていなければ `lm update <id> --clear expedite` で外す。基準: 印を放置すると、急ぐ理由の確かめられていない Bead が読み手に急ぎと誤読される。
- 同時件数の上限で拒否されたら、有効な割り込みを持つ Bead を先に閉じるか `--clear expedite` で外してから付ける。上限と最長期間の値は `lm coefficient show` で見る。基準: 上限を上げて通すと、割り込みが常態になり `P0` の段が意味を失う。
- 成果物が無いと着手できない技術的な前提は、割り込みではなく `lm dep add <id> <前提の id> --type blocks` で張る。基準: 前提に割り込みを付けると、下流が閉じたあとも前提だけが `P0` に残る。
- 実行者は、`lm update` に `--priority` か `--expedite` が付き `--reason` が「前提」「依存」を含む呼び出しを拒否し、`lm dep add <id> <前提の id> --type blocks` で張るよう案内する拡張を足してよい。この拒否は `lm` 本体には無く、足すかどうかは実行者が決める。

## 期限（`--due`）

- 期日に価値が依存する Bead に `lm create --due <RFC3339>`（または `lm update <id> --due <RFC3339>`）を付け、保存優先度を手で上げる代わりに期限で表す。期日の手前（先行時間）に入ると `lm` が実効 `P1` に上げる。基準: 手で上げた値は期日が過ぎても下がらず、期日の無い Bead と区別できなくなる。
- 今の処理量で間に合わない見込みかどうかの判定は実行者か利用者が行い、間に合わないときは割り込みを付ける。

## 順番の希望

- 「A の後で B をやりたい」が希望にすぎないときは、依存を張らずに B の保存優先度を A より下げる。B が A の成果物を要するときだけ `lm dep add <B> <A> --type blocks` を張る。基準: 希望を依存で表すと、A が止まったときに B まで Ready から消え、手の空いた実行者が拾えなくなる。

## 時間調整と保留

時間調整（昇格・減衰・保留）が並びに効くかは係数 `time_adjust` の値で決まる。今の値は `lm coefficient show` で見る。`on` のときは `lm ready` の既定の並びが時間調整後になり、`shadow` のときは既定の並びは変わらず、時間調整後の並びと保留の件数は `lm ready --time-adjusted` で引ける。`off` のときは並びが時間調整の前の実効優先度のままになる。

- `lm ready` が空・少ないときは、末尾の `- Held: <件数>` を見る（`shadow` なら `lm ready --time-adjusted` の末尾を見る）。保留の Bead は `lm blocked` に `← held: no demand since <時刻>` の印つきで並ぶ。基準: 保留を見ずに「やることが無い」と判断すると、要る Bead が隠れたまま取り消しへ進む。
- 保留から戻すときは、その Bead に需要を付ける。需要は、未完了のマイルストーンへの所属（`lm dep add <id> <Epic ID> --type parent-child`）・未完了の下流を塞ぐリンク（`lm dep add <下流> <id> --type blocks`）・期限（`--due`）のどれかである。需要が付けば書き込みを待たずに戻り、変更の出力の `## Newly ready` に出る。基準: 需要を付けずに戻すと、同じ時間でまた保留に入る。
- 需要を付けられないが今は要るときだけ、`lm update <id> --revive --reason "<要る理由>"` で手で戻す。進捗に数えるのは状態・claim・保存優先度・題・本文・外部参照・依存・期限・割り込み・重大度・手で戻した時刻の更新である。理由だけを残す `lm update <id> --reason "..."`・ラベルの付け替え・要約の更新はこの一覧の代わりにならないので、戻すときは `--revive` を使う。基準: 保留を避けるために空の更新を打つと、需要の無い Bead が並びに残り続け、減衰と保留が働かなくなる。
- 減衰（実効優先度が下限まで下がる）は並びを変えるだけで、保留は `lm ready` から外す。`eff=P<n>(decayed)` が付いた Bead は Ready に残っているので、急ぐなら需要か割り込みを付ける。

## 保留からの取り消し

- 保留のまま一定期間たった重大度 3・4 の Bead は、実行者が定期的に打つ `lm hold cancel` で `cancelled` になる（`time_adjust` が `on` のときだけ取り消す）。打つ前に `lm hold cancel --dry-run` で対象を確かめる。基準: 対象を見ずに打つと、需要の付け忘れで要る Bead が取り消される。
- 取り消された Bead が要るとわかったら、`lm update <id> --reopen --reason "<要る理由>"` で戻し、同時に需要を付ける。基準: 需要を付けずに戻すと、同じ期間ののちにまた取り消される。

## 自動起票（再検知）

- 同じ原因を繰り返し検知する仕組みは、原因ごとに決めたキーで `lm create --title "..." --redetect-key <キー>` を打つ。同じキーの未完了の Bead があれば新しく作られず、出力に `- Redetected: <ID>` が出て最後に検知した時刻だけが進む。最後の検知が再検知の窓の内にある Bead は需要ありとして扱われる。基準: キー無しで起票すると、同じ原因の Bead が検知のたびに増え、重複の整理に手が取られる。

## `eff=` の読み方

`lm ready`・`lm blocked`・`lm gate`・`lm list --sort priority` の行末の `eff=P<n>(<理由>)` は、保存値と違う実効優先度とその理由を示す。理由ごとに、値を変えたいときの手は次のとおり。

| 理由 | 意味 | 変えたいときの手 |
|---|---|---|
| Bead の ID | その Bead（塞いでいる下流か親）から引き上げが伝わった | 引き上げ元を閉じるか、リンクを `lm dep remove` で外す（外す前に `--dry-run` で変化を見る） |
| `expedite` | 有効な割り込みを持つ | `lm update <id> --clear expedite` |
| `due` | 期限の先行時間に入った | `lm update <id> --clear due` か `--due` で期限を付け直す |
| `aged` | 需要があり Ready のまま時間がたって昇格した（`time_adjust` が `on`、または `--time-adjusted`） | 着手するか、需要を外す |
| `decayed` | 需要が無く進捗も無いまま時間がたって減衰した（同上） | 需要を付けるか、保存優先度を見直す |

## 係数を変える

- 係数は `lm coefficient show` で今の値と設定時刻を見て、`lm coefficient set <キー> <値> --reason "<決め直す根拠の実測>"` で変える。1 回に 1 つのキーだけを変え、その効果が実測に出てから次のキーを変える。基準: 同時に複数を変えると、どの変更が並びを良くしたのか悪くしたのかの切り分けが曖昧になる。
- 決め直すきっかけは実測に置く: 昇格で上限の段に溜まる件数・保留から戻された件数・取り消しのあとに reopen された件数・割り込みの拒否件数。決め直すかどうかと値の良し悪しの判断は利用者か実行者が行う。
- `time_adjust` を `on` にするのは、`lm ready --time-adjusted` の並びと実際の拾い順の差を一定期間記録し、要る Bead が隠れていないことを確かめてからにする。基準: 確かめずに切り替えると、厳しすぎる係数が要る Bead を保留にして取り消しへ送る。

## 避ける形と代わりの手

| 避ける形 | 代わりの手 |
|---|---|
| 優先度に `0` を書く（`lm` が拒否する） | `--expedite <期間> --reason "..."` を付ける |
| 保留を避けるために理由だけ・ラベルだけの更新を打つ | 需要（親子・塞ぐリンク・期限）を付ける |
| 子や前提ごとに割り込みを付ける | 束の根の 1 件に付ける |
| 期日が近いので保存優先度を上げる | `--due` を付ける |
| 希望の順番を `blocks` で張る | 後にしたい側の保存優先度を下げる |
