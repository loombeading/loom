## マイルストーンの点検と調整

マイルストーンの定義（完了条件・名前・常設の SLO（Service Level Objective・サービスレベル目標）との区別）は [milestone.md](milestone.md) が正本である。本書は、マイルストーンが到達に向かっていないと分かったときに、どの順で何を直すかを定める。本書では、到達に向かっていない兆候として下の表の左列に挙げたものを「要調整の兆候」と呼ぶ。各兆候をどの `lm` コマンドの出力のどの値で見るかは表の「どこで見るか」列に示し、本書が受け持つのは、見つけた兆候を完了条件の意味を読んで調整する判断の部分である。

基準: 調整の順序と担い手を文書にしておかないと、点検のたびにセッションが順序を組み立て直し、人に回す範囲がぶれる。要調整の兆候をどう調整するかは完了条件の意味を読む判断なので機械検査にできず、セッションがこの手順に従う。

本書は、対話セッションが判定者を起動できる運用を前提に書く（対話セッション・判定者・実行者は [用語集](https://github.com/loombeading/loom/blob/main/docs/glossary.md)の同名の項）。判定者を置かない運用では、本書で「判定者」とある担い手を、`kind:adjudicate` の Gate を読んで `lm gate resolve` か `lm gate reject` で決める人に読み替える。本書で使う語は次の意味である。

- **SLO・常設の運用 Epic**: 終わりの無い目標と、その違反の起票を受ける `milestone` ラベルの無い Epic（[milestone.md](milestone.md)「常設の SLO との区別」）。
- **出荷判定の Gate**: 出荷版のマイルストーンを公開してよいかを決める `kind:adjudicate` の Gate。resolve すると版の公開作業が始まる。
- **完了条件を書き直す Bead**: マイルストーンの Epic の `done:` ラベル（完了条件）を書き直し、要らない子を Epic から外す作業を受け持つ Bead。調整の中で起票する。

### きっかけ

次のどれかが起きたら、対話セッションが本書の手順を回す。

- 利用者がマイルストーンの見通し・期日・妥当さを問うた。
- 実行者がマイルストーンについて `kind:adjudicate` の Gate を作った（到達済みなのに open など）。
- 出荷判定の Gate を resolve する前。

### 手順

1. `lm ahead` を打ち（期待する終了コード 0）、`## Milestones` の各マイルストーンの残数・Ready・作業中・Gate 待ちを読む。
2. 次の「要調整の兆候」に当たるものだけを、表の「どこで見るか」の値で拾う。どれにも当たらなければ何もしない。
3. 拾った項目ごとに、下の表の「調整」を行う。分岐の判断が要る項目は判定者（adjudicate）に件名・現状・選択肢・推奨と Bead ID を渡し、判定者が `lm update --reason` で記録した結論を `lm show` で確かめてから実行する。
4. 行った調整は、触った Bead ごとに `--reason` へ理由を書く。判定者の作業で消費したトークンも `lm ahead` の見積もりの元に含めるなら、`lm cost add` で調整した Bead に記録する（任意。[用語集](https://github.com/loombeading/loom/blob/main/docs/glossary.md)「token cost」）。

### 要調整の兆候ごとの調整

「どこで見るか」の `## Milestones` は `lm ahead` の節で、マイルストーン 1 件につき 1 行に `ready=`・`wip=`・`course=`・`gate=`・`remaining=`（残数）・`close/日=`・`残り日数=`・`eta=`（到達見込み）が並び、判定待ちの Gate があれば `judge=<件数>`、人の Gate を待っていれば末尾に `Gate 待ち` が付く。

| 要調整の兆候 | どこで見るか | 調整 | 誰が |
|---|---|---|---|
| 発散（起票が close を上回り続ける） | `## Milestones` の行の `eta=発散`（片側だけなら `eta=<日時>〜発散`） | 完了条件に要らない子を Epic から外す。どの子を外すかは完了条件を書き直す Bead が決め、その Bead を外される側の作業より先に拾わせるため、その Bead だけを P1 にする（割り込みは今やる作業専用で、順番付けに使わない。SKILL.md「優先度」）。発散しているマイルストーンに新しい子は足さない | 完了条件を書き直す Bead・判定者 |
| 完了条件が袋の形（子がすべて終端になることを条件にしている・`done:` ラベルが無い・実行者が測れない `done:` ラベルがある） | `lm show <Epic ID>` の `labels` に `done:` が無いか、`done:` の種別が実行者の測れる `wait:` の種別に無い | 完了条件を、実行者が `wait:` ラベルと同じ書式で測れる形（milestone.md「定義」）に書き直す。実行者に無い測り方が要るなら、その測り方を足す Bead を起票して Epic を `blocks` で待たせる | 判定者 |
| 到達済みなのに open | `## Milestones` に `remaining=0` の行が残っているか、`lm show <Epic ID>` の `done:` の条件を実物が満たしているのに Epic の `status` が `open` | Epic を close し、完了条件に無関係な子の移し先（別のマイルストーンか常設の運用 Epic）を決めて付け替える | 判定者 |
| 出荷版の期日に間に合わない | `## Milestones` の行の `eta=` の遅い側（`〜` の右）が版名の期日より後か、`残り日数=見込み無し` | 期日（版名）を変えるか、子を外して間に合わせるかを決める | 利用者（判定者が人の判断が要ると結論したあと `--adjudicated-by` 付きの `kind:human` Gate で渡す） |
| 公開の鎖に人の Gate がある | `## Milestones` の行の末尾の `Gate 待ち`。どの Gate かは `lm gate` で見る | 人の Gate を含む鎖の先頭を、完了条件を書き直す Bead を待たずに P1 にする。公開の承認そのものは人の Gate で待つ | 対話セッション・利用者 |
| 出荷の日がまだ来ていない | 出荷の日より前なのに、出荷作業の Bead が `lm ready` に出ている | 出荷作業の Bead を `wait:date:<日付>` の external Gate で塞ぐ | 対話セッション |
| 無所属・優先度の逆転 | `lm show <ID>` の `## Dependencies` にマイルストーンの Epic への `parent-child` が無く `labels` に `exempt:milestone` も無いか、`priority` が親の Epic より高い | 所属するマイルストーンの Epic を `--parent` で付け、子の優先度を Epic と同じ段に揃える。どこにも所属しないなら `--reason` にそう書く | 対話セッション |
| SLO の超過 | `lm` は SLO を測らない。SLO を測る側（実行者など）の実測値が目標を超えている | 実測を SLO と並べ、根本原因・構造の改善・規約化の Bead に分けて起票する | 対話セッション |
| 前提の成果が無くても作れる部分を持つ Bead が、その前提を `blocks` で待っている | `lm blocked` の行の `← blocked by:` に出る前提を、Bead の本文と照らして見る | 前提を要らない部分は先に作れるので、その `blocks` を `lm dep remove` で外し、前提を要る部分だけを別の Bead に分けて `blocks` で待たせる | 対話セッション |
| 同じ中身の Bead が重複している | `lm search <語>` で同じ中身の Bead が 2 件以上出る | 新しい方を `lm dep add <新しい方> <古い方> --type duplicates` で古い方に結び付け、`lm close` する | 対話セッション |

### 人に回す範囲

人に回すのは版名・期日・公開の承認だけにする。それ以外の分岐は判定者に振る。基準: 判定者に振れる判断を人へ回すと、利用者の応答待ちでマイルストーンが止まる。
