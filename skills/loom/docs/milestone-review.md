## マイルストーンの点検と調整

マイルストーンの定義（完了条件・名前・常設の SLO（Service Level Objective・サービスレベル目標）との区別）は [milestone.md](milestone.md) が正本である。本書は、マイルストーンが到達に向かっていないと分かったときに、どの順で何を直すかを定める。本書では、到達に向かっていない兆候として下の表の左列に挙げたものを「要調整の兆候」と呼ぶ。各兆候をどの `lm` コマンドの出力のどの値で見るかは表の「どこで見るか」列に示し、本書が受け持つのは、見つけた兆候を完了条件の意味を読んで調整する判断の部分である。

基準: 調整の順序と担い手を文書にしておかないと、点検のたびにセッションが順序を組み立て直し、人に回す範囲がぶれる。要調整の兆候をどう調整するかは完了条件の意味を読む判断で、`lm` の出力だけでは決まらないので、セッションがこの手順に従う。

本書は、対話セッションが判定者を起動できる運用を前提に書く（対話セッション・判定者・実行者は [用語集](https://github.com/loombeading/loom/blob/main/docs/glossary.md)の同名の項）。判定者を置かない運用では、本書で「判定者」とある担い手を、`kind:adjudicate` の Gate を読んで `lm gate resolve` か `lm gate reject` で決める人に読み替える。実行者を用意しない既定の運用（[チュートリアル](https://github.com/loombeading/loom/blob/main/docs/tutorial.md)「実行者を用意しないとき」）では、本書で実行者が行うとある Gate の作成と `done:` ラベルの確かめを、対話セッションか利用者が `lm ahead` を読んで行い、本書の手順も同じ担い手が回す。本書で使う語は次の意味である。

- **SLO・常設の運用 Epic**: 終わりの無い目標と、その違反の起票を受ける `milestone:<名前>` ラベルの無い Epic（[milestone.md](milestone.md)「常設の SLO との区別」）。
- **出荷判定の Gate**: 出荷版のマイルストーンを公開してよいかを決める `kind:adjudicate` の Gate。resolve すると版の公開作業が始まる。マイルストーンの Epic の `done:` ラベルを実物が満たしたら、対話セッション（実行者を用意するなら実行者）が、版の公開作業の Bead を塞ぐ形で作る。例: `lm gate create --kind adjudicate --subject "<版名> を出荷してよいか" --current "<Epic ID> の done: を満たした" --proposal "<版名> を公開する" --check "公開作業の Bead が Ready になる" --blocks <公開作業の Bead の ID>`。
- **完了条件を書き直す Bead**: マイルストーンの Epic の `done:` ラベル（完了条件）を書き直し、要らない子を Epic から外す作業を受け持つ Bead。調整の中で、本書の手順を回す対話セッションが `lm create --parent <Epic ID>` で起票する。
- **発散**: マイルストーンの残りを減らす close の速さが、配下への起票の速さ以下で、到達見込みの日時が計算できない状態。`lm ahead` は速い側・遅い側の見込みの両方が発散なら `eta=発散`、遅い側だけなら `eta=<日時>〜発散` と出す。

### きっかけ

次のどれかが起きたら、対話セッションが本書の手順を回す。

- 利用者がマイルストーンの見通し・期日・妥当さを問うた。
- 実行者がマイルストーンについて `kind:adjudicate` の Gate を作った（到達済みなのに open など）。
- 出荷判定の Gate を resolve する前。

### 手順

1. `lm ahead` を打ち（期待する終了コード 0）、`## Milestones` の各マイルストーンの残数・Ready・作業中・Gate 待ちを読む。
2. 次の「要調整の兆候」に当たるものだけを、表の「どこで見るか」の値で拾う。どれにも当たらなければ、調整せずにこの手順を終える。
3. 拾った項目ごとに、下の表の「調整」を行う。分岐の判断が要る項目は判定者（adjudicate）に件名・現状・選択肢・推奨と Bead ID を渡し、判定者が `lm update --reason` で記録した結論を `lm show` で確かめてから実行する。
4. 行った調整は、触った Bead ごとに `--reason` へ理由を書く。判定者の作業で消費したトークンも `lm ahead` の見積もりの元に含めるなら、`lm cost add` で調整した Bead に記録する（任意。[用語集](https://github.com/loombeading/loom/blob/main/docs/glossary.md)「token cost」）。

### 要調整の兆候ごとの調整

「どこで見るか」の `## Milestones` は `lm ahead` の節で、マイルストーン 1 件につき 1 行に `ready=`・`wip=`・`course=`・`gate=`・`remaining=`（残数）・`close/日=`・`残り日数=`・`eta=`（到達見込み）が並び、判定待ちの Gate があれば `judge=<件数>`、人の Gate を待っていれば末尾に `Gate 待ち` が付く。

| 要調整の兆候 | どこで見るか | 調整 | 誰が |
|---|---|---|---|
| 発散（起票が close を上回り続ける） | `## Milestones` の行の `eta=発散`（片側だけなら `eta=<日時>〜発散`） | 「リリースを守る手」の 3 つから選ぶ。完了条件を書き直す Bead を起票し、その Bead が完了条件を期日までに届く範囲へ書き直し（手 1）、要らない子を Epic から外して次の版へ付け替えるか（手 2。付け替え先の無い子は、外す前に `lm update <子> --add-label exempt:milestone --reason <理由>` で無所属を記録する。`create.require_milestone` が真なら、記録せずに外して無所属になる `lm dep remove` は拒否される）、マイルストーンを分割する（手 3）。その Bead を外される側の作業より先に拾わせるため、その Bead だけを P1 にする（割り込みは今やる作業専用なので、順番付けには P1〜P4 を使う。SKILL.md「優先度」）。発散しているマイルストーンに新しい子は足さない | 完了条件を書き直す Bead・判定者 |
| 完了条件が実物で測れない（子がすべて終端になることだけを条件にしていて、何ができたら到達かを書いていない・`done:` ラベルが無い・実行者が測れない `done:` ラベルがある） | `lm show <Epic ID>` の `labels` に `done:` が無いか、`done:` の種別が実行者の測れる `wait:` の種別に無い | 完了条件を、実行者が `wait:` ラベルと同じ書式で測れる形（milestone.md「定義」）に書き直す。実行者に無い測り方が要るなら、その測り方を足す Bead を起票して Epic を `blocks` で待たせる | 判定者 |
| 到達済みなのに open | `## Milestones` に `remaining=0` の行が残っているか、`lm show <Epic ID>` の `done:` の条件を実物が満たしているのに Epic の `status` が `open` | Epic を close し、完了条件に無関係な子の移し先（別のマイルストーンか常設の運用 Epic）を決めて付け替える | 判定者 |
| 出荷版の期日に間に合わない | `## Milestones` の行の `eta=` の遅い側（`〜` の右）が版名の期日より後か、`残り日数=見込み無し` | 「リリースを守る手」の 3 つから 1 つを選んで判定者に提案し、判定者が決める。期日（版名）を変えるのは利用者の判断で、提案の選択肢に入れない | 判定者（期日と版名の変更は、判定者が人の判断が要ると結論したあと `--adjudicated-by` 付きの `kind:human` Gate で利用者に渡す） |
| 版の公開作業の Bead を人の Gate が塞いでいる（直接か、`blocks` を辿った前提のどこかで） | `## Milestones` の行の末尾の `Gate 待ち`。どの Gate かは `lm gate` で、塞がれている前提の連なりは `lm blocked` の `← blocked by:` を辿って見る | その連なりのうち、前提を持たず今着手できる Bead（`lm blocked` の `← blocked by:` を辿った末端）を、完了条件を書き直す Bead を待たずに P1 にする。公開の承認そのものは人の Gate で待つ | 対話セッション・利用者 |
| 出荷の日がまだ来ていない | 出荷の日より前なのに、出荷作業の Bead が `lm ready` に出ている | 出荷作業の Bead を `wait:date:<日付>` の external Gate で塞ぐ | 対話セッション |

| SLO の超過 | SLO を測るのは `lm` の外の側で、その側（実行者など）の実測値が目標を超えている | 実測を SLO と並べ、根本原因・構造の改善・規約化の Bead に分けて起票する | 対話セッション |
| 発散している段の後ろに、先にやると無駄な起動やマイルストーンの停滞を止める Bead（同じ起票が繰り返し流れ込むのを止める Bead・効率化の切り替えを塞いでいる Bead・複数のマイルストーンを `blocks` で塞いでいる Bead など、他の多くの作業を止めている Bead）が埋もれている | `lm ahead` の段の行の `cont=` が発散し、その段の Ready の後ろの方にその Bead がいる | 利用者に聞き返さずその場で `lm update <id> --priority 1` にし（所属マイルストーンの Epic の段が上限になるときは Epic も合わせて上げる）、要る前提は `lm dep add` で張り、`--reason` に消え続ける資源の止血であることを書く | 対話セッション・判定者 |
| 前提の成果が無くても作れる部分を持つ Bead が、その前提を `blocks` で待っている | `lm blocked` の行の `← blocked by:` に出る前提を、Bead の本文と照らして見る | 前提を要らない部分は先に作れるので、その `blocks` を `lm dep remove` で外し、前提を要る部分だけを別の Bead に分けて `blocks` で待たせる | 対話セッション |
| 同じ中身の Bead が重複している | `lm search <語>` で同じ中身の Bead が 2 件以上出る | 新しい方を `lm dep add <新しい方> <古い方> --type duplicates` で古い方に結び付け、`lm close` する | 対話セッション |

### リリースを守る手

出荷版のマイルストーンが期日に間に合わない見込みになったら、対話セッション・判定者・実行者は次の 3 つの手からだけ選ぶ。

1. ゴールを調整する: マイルストーンの完了条件（`done:` ラベル）を、期日までに届く範囲に書き直す。
2. マイルストーンの状態を調整する: 到達済みなら close し、この出荷版に要らないマイルストーンや子は出荷版から外して次の版へ付け替える。
3. マイルストーンを分割する: 期日内に届く部分を今回の出荷版に残し、残りを新しいマイルストーンにして次の版に付ける。

起票の件数・起票の流入・優先度の順番を動かしたくなったら、代わりに上の 3 つのどれかを判定者に提案する。期日と版名の変更は利用者の判断なので（次節）、エージェントは提案の選択肢に入れず、判定者が人の判断が要ると結論したときだけ `kind:human` の Gate で渡す。

基準: 件数や順番を動かす手（重複の統合・起票元の抑制・後送り・他の版との順番の入れ替え・期日の延期）は、残る仕事の量を変えずに見込みの見かけだけを変えるので、選んでも出荷版は守れず、判定者がその比較に時間を使う。どの手が件数や順番を動かす手かは提案の中身を読んで決めるので、選択肢を出す側がこの節に従う。

### 人に回す範囲

既定では、版名・期日・公開の承認と、受入・出荷・方針の判断を利用者に回し、それ以外の分岐（どの Bead をどの Epic に付けるか等の手順の判断）を判定者に振る。実行者の文書が「判定者に委ねる判断の範囲」を上書きしていれば、その範囲は判定者に振る。基準: 受入・出荷を利用者の承認なしに判定者が決めると、導入先で人の承認を経ずに変更が出荷される。
